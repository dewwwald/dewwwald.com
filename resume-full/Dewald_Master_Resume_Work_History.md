## Resume Formatting Decisions From Thread

- Use a simple, single-column resume for applications.
- Use Google Docs or Word as the source of truth, then export as PDF.
- Do not use HTML as the primary resume format for ATS/recruiter workflows.
- HTML can be useful later for a portfolio or personal website version.
- Avoid multi-column “cool tricks” layouts for manager applications.
- Use a boring-looking, high-signal resume.
- Final application resume should be 2 pages maximum.
- Markdown `#` headings are fine in the drafting/export version, but remove visible markdown symbols in Google Docs/PDF.
- Use visual headings instead of visible `#` characters in the final document.
- Keep **Experience** as a section heading; use “Experience” rather than “Professional Experience” to save space.
- Do not remove the experience heading entirely because it gives recruiters a visual anchor.
- Timeline layout can be used if it remains ATS-safe:
  - Date line
  - Company — Role
  - Location
  - Bullets
- Avoid overly light grey dates because they may print poorly or be harder to scan.
- Remove colons from section headings, for example use **Leadership & Platform Highlights**, not **Leadership & Platform Highlights:**.
- Compress older roles so they do not compete with Intuit and BigTeam.
- Use 4–6 bullets for the main recent role, not 8+.
- Collapse repeated foundation points into one strong bullet.
- Put the strongest, most role-relevant material in summary, highlights, Intuit Mailchimp, BigTeam, and technical skills.
